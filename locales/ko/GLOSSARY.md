Tone: 합니다/하세요 in sentences and error messages ("…을 선택하세요", "…하지 못했습니다"), as Windows, Samsung and Naver apps address a Korean user; no pronoun for "you". Buttons, labels, tabs and column headings are nouns or noun phrases (변환, 다운로드, 취소, 초기화, 저장, 완료). Short status text and hints under options end in a noun or 됨/없음 form ("가장 가까운 악기로 연주", "악기 3개 제외", "변경 사항 없음"). Errors say what happened in plain words ("파일을 읽을 수 없습니다. MIDI 파일이 아닌 것 같습니다"); limits are said plainly ("프리셋은 최대 20개까지 저장할 수 있습니다", not "최대 개수에 도달했습니다"). Register: friendly and plain, like one musician explaining to another — "건드리지 않습니다", "바꿔 줍니다", "여러 개도 됩니다" — no officialese or calques of English structure (avoid "…간에 변환", "…을 위한"). Counts use the counter 개 after the number ("악기 { $count }개"); Korean has no plural, so number selects keep only `*[other]` (plus `[0]` where the zero sentence differs).

Particles after names we don't control (engine names, drum names, file names, e-mail addresses): never guess 을/를, 이/가, (으)로. Use particles that work after any word (에, 에서, 의, 용, 입니다), add a noun ("{ $file } 파일을", "{ $email } 주소로"), or rephrase ("원본 { $source }, 대상 { $target }"). Particles are written directly only where the ending is fixed: "Drumverter는/를" (…버터), "{ $engineMidi }를" / "{ $sourceMidi }를" (always ends in "MIDI" = 미디), "GitHub 이슈를".

English kept: drum and family names (China, crash, Tom 3 — inside examples), engine and product names, MIDI, Drumverter, DAW, GitHub, note names (C1, D#2, C-1, C-2), file extensions (.mid, .zip, .json), Enter / Ctrl+Enter (key names as printed on Korean keyboards), and FAQ as the short navigation label (Korean sites use it as is; the page heading is 자주 묻는 질문). Drummer jargon uses the standard Korean loanwords drummers say: 고스트 노트 (ghost notes), 림샷 (rimshot), 프리셋 (preset), 트랙, 채널, 그루브, 킷.
